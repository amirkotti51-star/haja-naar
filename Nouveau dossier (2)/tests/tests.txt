# Tests

## Test 1 - Discover and open a provider profile [sanity]
Viewport: desktop
Covers: service discovery, provider profile, direct contact, clean provider URL
Description: Verifies the core customer journey and that provider profiles use a stable clean URL.
Steps:
1. Search for a service and open a result.
2. Open the provider profile.
3. Inspect the browser URL and refresh the page.
Expected: The provider profile uses /provider/<name>/<id> and remains reachable after refresh.

## Test 2 - Open a clean service URL
Viewport: desktop
Covers: clean service URL, service detail, dynamic SEO title and canonical
Description: Verifies service detail pages have stable shareable URLs and SEO metadata.
Steps:
1. Open a service result.
2. Inspect the browser URL.
3. Refresh the page.
Expected: The URL uses /service/<name>/<id>, the service detail opens again, and the title/canonical describe the service.

## Test 3 - Browse clean location links and search
Viewport: mobile
Covers: clean location URLs, city navigation, service search/filtering, responsive navigation
Description: Verifies location landing pages and search remain usable on mobile.
Steps:
1. Open a governorate page with available services.
2. Open one of its city links.
3. Search for a matching service and open it.
Expected: The location URL uses /services/<governorate>/<city> and the matching service opens on its clean service URL.

## Test 4 - Verify crawler discovery endpoints
Viewport: desktop
Covers: /robots.txt, /sitemap.xml, clean service/provider/location sitemap coverage
Description: Verifies crawler-facing endpoints expose the public pages that should be indexed.
Steps:
1. Open /robots.txt.
2. Open /sitemap.xml.
3. Inspect the sitemap entries.
Expected: robots.txt references sitemap.xml and the sitemap opens as valid XML containing the homepage and public /services/<governorate> location URLs.

## Test 5 - Empty search and reset guardrail
Viewport: mobile
Covers: search empty state, filter reset, non-matching query handling
Description: Verifies a non-matching search does not show misleading results and can be cleared.
Steps:
1. Enter a random phrase that does not match any published service.
2. Submit the search.
3. Select "مسح الفلاتر".
Expected: An empty-state message appears and clearing filters restores the service list.
